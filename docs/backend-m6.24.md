# Backend report — M6.24 maternity units (founder ruling at M6.23)

M6.24 builds the maternity category the founder's M6.23
ruling adopted (repair B3), on the re-scoped signal the
step's first check proved. The original premise — that
the filed CQC service types could select maternity
units — is false: the directory's "Service types" column
is an organisational vocabulary with no maternity value
in it, and the maternity hospitals file there as plain
"Hospital". The signal is the CQC ratings file's
"Service / Population Group" value "Maternity", which
the health loader already parsed row by row (for the
emergency-department flag and the overall rating) and
discarded. This step files those groups and selects on
them. No CQC rating is served by this step: the ratings
are filed (cqc_ratings, migration 0005) but no brain
serves them — serving them is the sibling step M6.25,
named below and not built here.

## Divergences from the brief, and how they were settled

1. **"Overall" does not file as a group.** The brief
   says to file each hospital's ratings population
   groups; the ratings file uses the same column for
   the overall rating's rows, whose value is "Overall".
   Filing it would put a rating marker in a column
   documented as service and population groups, and the
   rating itself already files in cqc_ratings. The
   loader files every other published value verbatim;
   the exclusion is documented in the migration header,
   the loader's header comment and a loader test.
2. **No golden-replay cells were added.** The replay's
   nearby assertions are targeted cells, and the
   maternity goldens are locked at brain level against
   the same filed fixture data the replay files; the
   replay files the health fixture in CI, so the filed
   column is exercised end to end there regardless.
